# Ruwriter

跨平台小说与文本写作软件，以 [Cove](https://github.com/AlexCat315/Cove) 的 `cove-ui` 为 UI/宿主框架。Rust 2024，桌面、iOS、Android 共用同一套 Rust 视图与文档模型。

默认是小说模式：正文就是纯文本，没有 `#`、`**`，新稿存为 `.txt`，章节靠「第一章 雨夜」这样的行来分；需要 Markdown 的人可以在「显示 → Markdown 模式」切回去。定位仍是「本地文件即真相」：文件可直接被任何编辑器打开，`.ruwriter/` 只放派生信息与可重建状态。能力覆盖、竞品对标与版本路线见 [`docs/PRODUCT-ROADMAP.md`](docs/PRODUCT-ROADMAP.md)。

## 下载

[GitHub Releases](https://github.com/AlexCat315/Ruwriter/releases) 提供 macOS（Apple 芯片 / Intel）的 `.dmg`、Windows x64 的 `.exe` 安装程序与 Linux x64 的 `.deb`。当前包没有 Apple 开发者签名，macOS 首次打开需右键「打开」或在「系统设置 → 隐私与安全性」允许；Windows 可能提示 SmartScreen，选择「更多信息 → 仍要运行」。iOS 与 Android 需要各自的签名材料，暂不提供安装包。

## AI 助手

在正文停到要接写的位置，再点编辑器工具栏的「AI 助手」。有选区时初次打开进入润色。宽窗口在正文旁显示「写作对话」，窄窗口使用全宽界面。每篇文稿有独立的对话。

第一次续写先显示「先梳理作品」。Ruwriter 按所选范围分批读稿，当前文稿读到落笔点，整理剧情、角色卡、关系、角色说法与待续线索。核对题材、叙事口味和角色动机，再补一句接下来的方向后点「确认并续写」。也可以直接在面板顶部的「作品资料」填写。确认后的资料按作品保存。

「角色说法」用来记录自述、传言、隐瞒、隐喻以及各角色知道什么。「作者私设」用来写真实动机和能揭晓的时机。私设只交给审稿回合，起草回合使用当前视角可见的资料。审稿发现提前揭露或把未经证实的说法写成事实时，会要求修订并挡住采纳。

1. 在底部输入框说想怎么写，例如「她接过钥匙，写到她关门为止」。Enter 发送，Shift+Enter 换行。续写会带上当前光标前文，面板会随光标更新落笔位置。提交后，这份草稿保留原位置。再发「续写」会从正文当前落笔点重新起草。
2. 续写先梳理接续点，再流式显示正文。如果决定下一步必须确认一句话的潜台词或人物关系走向，面板会引用原文并先问一个具体问题。也可以从输入框下方的模式菜单选择「先确认本场」，先看助手打算怎样推进，再决定。回答会保留原要求和落笔位置。角色偏离会挡住采纳。「场景推演」可以查看当前反应依据和复用的改稿经验。
3. 采纳时，续写接到原落笔点，润色替换原选区。两种操作都可以在正文撤销。正文有其他修改时，Ruwriter 只在原位置仍能唯一识别时写入。也可以随时复制草稿。

改完草稿后，可点「记住这次改法」。自己在正文写了一版，也可以选中它，再点「用正文选区作为改写版」。「作品资料」里的 DiffData 会显示改动。可用顿号分隔角色名或场景关键词，再补上应沿用的经验。命中当前请求或落笔点附近原文的记录会优先进入本轮计划。

「对话记录」会按文稿保存发送和回复，重启后可查看并接着提问。可导出 JSON，也可导入同格式存档并追加去重。导入的草稿作为历史查看，需要写回时可复制。

「参考资料与模型」内可以选择检索范围和模型。作品资料按顶层作品文件夹保存在本地，独立文稿各有自己的资料。记忆可记录人物或情节、原文出处，并可置顶或标记待复核。文风页可维护文风要求、避用表达和作者认可的样段。

续写按当前场景的原文取样，有作者认可的样段时再选取相近的参考。人名和设定从可核对的原文提取，样段中的事件不会作为当前剧情。审稿指出有原文依据的文风或连续性问题时，助手会尝试一次局部修订。复审确认问题减少且没有新增类型的问题，才会替换候选稿。

单文件长篇按章名或 Markdown 标题建立目录，多卷作品可按顶层文件夹检索。选择「本文稿」或「作品文件夹」后，Ruwriter 先在本机搜索相关原文，再把命中的片段交给模型。启用工具调用的模型还可分页查目录、换关键词或回读章节。续写时当前文稿落笔点之后的原文不会参与检索。「原文来源」可以查看文稿、章节和行号。资料库根目录的文稿会明确显示「整个资料库」。

「管理模型」支持本机 Ollama、LM Studio 和 OpenAI 兼容的 HTTPS 服务。可通过「获取模型列表」选模型，也可以手填模型名。同一个服务的多个模型共用当前应用会话的 API 密钥。可以选一个模型起草，也可以勾选最多四个并行生成，再采纳其中一份。密钥在重启应用后按服务重新填写。

## 云同步

本地 `documents/**.txt` 仍是唯一真相；云同步只做备份与跨设备交换，不改变正文格式，也不会把缩进、Markdown 记号或任何占位字符写进文件。

登录不经过 Ruwriter 自己的 Token 输入框：直接复用本机 [GitHub CLI](https://cli.github.com/) 的登录态。终端执行一次：

```sh
gh auth login
```

Ruwriter 在每次同步时向 `gh` 读取一次凭据，用完即丢，不落盘、不写进资料库。没安装 `gh` 或未登录时，对话框会直接给出这条命令。凭据需要 `gist` 权限，`gh auth login` 默认包含。

每个资料库自动对应一个**私有 Gist**。同步配置跟随资料库，保存在隐藏的 `.ruwriter/state.json` 中。换电脑时复制整个资料库文件夹（包括 `.ruwriter`），登录同一个 GitHub 账号，再打开该资料库同步。Gist 内一篇文稿一个扁平纯文本文件 `doc_<uid>.txt`，文件夹、标题、摘要、状态、标签、置顶等放在 `ruwriter-manifest.json`。

合并按「本地 / 上次同步基线 / 云端」三方比较：只改一边就同步那一边；两边都改时本地版本上传，同时把云端版本另存为「原名（云端冲突 日期 时间）.txt」；云端删除且本地未改时移入废纸篓；本地删除会写 tombstone，避免第三台设备把文稿复活。空文稿不写正文文件（Gist API 不接受空内容），清单里的空哈希负责把它还原为空。

入口：`文件 → 云同步…` 或 `⌘K` 输入「云同步」。

## 结构

| 目录 | 内容 |
| --- | --- |
| `crates/core` | 文档模型、资料库（集合、置顶、废纸篓、搜索、设置）、原子写入、会话状态、字数统计；无 UI 依赖，可单独测试 |
| `src/model.rs` | 视图共享的控制器，按变化频率拆分信号，打字只重组显示它的视图 |
| `src/views` | 窗口外壳、侧栏、文稿列表、编辑器、命令面板 |
| `src/markdown_syntax.rs` | 编辑器的 Markdown 着色（接入 Cove `syntax_color_at_utf8_offset`） |
| `src/menu_bar.rs` / `src/shortcuts.rs` | 原生菜单栏与快捷键 |
| `src/theme.rs` | 纸张色浅色主题、暖炭色深色主题、编辑器字体 |
| `Platforms` | macOS / iOS / Windows / Linux / Android 清单与打包资源 |
| `xtask` | 复用 Cove 的 `cove-package` 打包、签名与装机 |

## 构建

`../Cove` 必须存在并完成过一次 `cargo cove setup`。AI 助手依赖 Cove 的 `cove-agent` 适配层。发布工作流按 `.github/workflows/release.yml` 的 `COVE_REF` 检出 Cove，同时应用 `patches/cove-agent-streaming.patch`，将 Cove 的流式输出和修订差异接口补入固定版本。

```sh
cargo build --workspace
cargo run -p ruwriter
cargo test --workspace
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
```

打包：

```sh
cargo xtask package mac --release
cargo xtask package windows --release
cargo xtask package linux --release
cargo xtask package android --release
cargo xtask package ios --simulator
```

## 文稿信息

每篇文稿可以有自己的摘要、状态（草稿 / 修订中 / 定稿 / 归档）和标签。这三样只写进 `.ruwriter/state.json`，不写进正文文件：正文始终是可直接带走、可被任何编辑器打开的原文。列表行的第二行显示自定义摘要（没写就显示正文摘录），第三行左侧是状态与 `#标签`。搜索同时匹配标题、正文摘录、摘要和标签。

## 数据位置

`library.json` 与 `documents/` 位于各平台的用户文档目录；`RUWRITER_DATA_DIR` 可覆盖根目录。每次编辑即时原子落盘，退出不丢内容。资料库内的文件在保存时以标题命名（`标题-1a2b3c4d.md`）；通过「打开」或系统「打开方式」导入的外部文件写回原路径、保留原名。旧版索引缺少的摘要与字数在启动时补齐。

## 已知限制

- 编辑器只能着色，不能改变字号或字重，标题以颜色区分。
- 外部文件移到废纸篓后永久删除只移出索引，不删除磁盘文件。
- 系统外观在 macOS、Windows、iOS、Android 上跟随；Linux 由 SDL 报告未知时按浅色处理。
- 本机只验证了 macOS；iOS / Android / Windows / Linux 的完整 UI 未在本机交叉编译（Cove 原生依赖需要对应工具链），核心 crate 已在这些目标上通过 `cargo check`。
